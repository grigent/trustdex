# Support

## Where to ask

Use a GitHub issue when you have a reproducible bug, compatibility problem, or feature proposal. Choose the closest issue form and provide a minimal configuration with all credentials and private endpoints replaced.

Before opening an issue:

- read the README and docs/THREAT_MODEL.md
- try the latest release or current main branch
- run trustdex --version, npm test, and npm run check when relevant
- search existing issues and pull requests

## What to include

A useful report includes the operating system, Node.js version, TrustDex version or commit, command, redacted input shape, observed output, expected outcome, and whether the behavior changes under another policy pack.

Never post tokens, passwords, private URLs, private signing keys, customer data, or proprietary prompts.

## Security issues

Do not use a public issue for exploitable vulnerabilities. Follow SECURITY.md.

## Scope and response

Support is community best effort with no service-level agreement. TrustDex can explain its own classifications and policies, but it cannot certify third-party software or provide incident response for an extension that TrustDex inspected.
