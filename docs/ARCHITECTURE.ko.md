# 아키텍처

<p align="right">
  <a href="./ARCHITECTURE.md">English</a> | <strong>한국어</strong>
</p>

TrustDex는 관찰, 정책, 게이트 및 검토 증거를 분리하는 의존성 없는 Node.js CLI입니다.

## 데이터 흐름

1. 어댑터가 MCP JSON 파일, Codex TOML의 제한된 하위 집합, 스킬 또는 플러그인 매니페스트를 읽습니다.
2. 검사가 소스를 정규화하고 관찰 가능한 신호를 생성합니다. 비밀 값은 보고서에 보관하지 않습니다.
3. 선택적인 신뢰 저장소 주장이 명시적인 출처 증거를 연결합니다.
4. 정책 엔진이 ALLOW, ASK 또는 BLOCK을 생성합니다.
5. 게이트가 승인된 설정만 출력합니다.
6. 스냅샷과 서명된 신뢰 기록을 통해 이후 드리프트를 검토할 수 있습니다.

게이트가 강제 적용 경계입니다. 보고서만으로는 에이전트가 검토되지 않은 확장을 불러오는 것을 막을 수 없습니다.

## 모듈

| 영역 | 책임 |
| --- | --- |
| `src/inspect.mjs` | MCP 소스 분류, 민감 정보 제거, 지문 생성 및 신호 |
| `src/codex-config.mjs` | 안전하게 실패하는 Codex MCP 전용 파싱 및 섹션 필터링 |
| `src/extensions.mjs` | 스킬 및 플러그인 매니페스트 검사 |
| `src/provenance.mjs` | 명시적인 로컬 신뢰 저장소 주장 |
| `src/provenance-online.mjs` | 사용자가 호출하는 GitHub, npm 및 MCP Registry 관찰과 로컬 아티팩트 다이제스트 검증 |
| `src/policy.mjs` | 단조로운 정책 평가. 신호는 심각도를 높일 수 있음 |
| `src/gate.mjs` | 승인된 MCP 항목만 출력 |
| `src/snapshot.mjs` | 결정론적 신뢰 관련 상태 및 드리프트 |
| `src/trust-record.mjs` | Ed25519 검토 기록 서명 및 검증 |
| `src/review.mjs` | 서명된 기준선 비교 |

## 보안 불변 조건

- 검사는 검사 대상 확장을 실행해서는 안 됩니다.
- 비밀 값은 출력하거나 스냅샷에 저장해서는 안 됩니다.
- 알 수 없는 증거가 신뢰로 바뀌어서는 안 됩니다.
- 차단 신호의 심각도를 출처 정보로 낮춰서는 안 됩니다.
- 지원하지 않는 보안 관련 구문은 안전하게 실패해야 합니다.
- 네트워크 조회는 명시적으로 수행하며, 관찰은 승인이 아닙니다.
- ALLOW는 정책 결과이지 안전 인증이 아닙니다.

## 의존성 정책

현재 런타임 코드는 Node.js 기본 제공 기능만 사용합니다. 새로운 의존성을 추가하려면 해당 기능을 플랫폼만으로 합리적으로 구현할 수 없는 이유, 패키지의 유지관리 및 보안 상태, 공급망 경계에 미치는 영향을 설명하는 이슈가 필요합니다.
