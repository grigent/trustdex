# 아키텍처

<p align="right">
  <a href="./ARCHITECTURE.md">English</a> | <strong>한국어</strong>
</p>

TrustDex는 관찰, 정책, 게이트 및 검토 증거를 분리하는 의존성 없는 Node.js CLI입니다.

## 데이터 흐름

1. 어댑터가 MCP JSON 파일, Codex TOML의 제한된 하위 집합, Claude/Codex 권한 설정 파일, 스킬 또는 플러그인 매니페스트를 읽습니다.
2. 검사가 소스를 정규화하고 관찰 가능한 신호를 생성합니다. 비밀 값은 보고서에 보관하지 않습니다.
3. 선택적인 신뢰 저장소 주장이 명시적인 출처 증거를 연결합니다.
4. 정책 엔진이 ALLOW, ASK 또는 BLOCK을 생성합니다.
5. 게이트가 승인된 설정만 출력합니다.
6. MCP 스냅샷, 권한 상태 스냅샷, 출처–권한 결합 스냅샷 및 서명된 신뢰 기록을 통해 이후 드리프트를 검토할 수 있습니다.
7. 명시적으로 전달된 값 없는 런타임 인벤토리를 검토된 연결과 대조할 수 있습니다. TrustDex는 런타임을 자동으로 찾거나 가로채지 않습니다.

게이트가 강제 적용 경계입니다. 보고서만으로는 에이전트가 검토되지 않은 확장을 불러오는 것을 막을 수 없습니다.

## 보안 불변 조건

- 검사는 검사 대상 확장을 실행해서는 안 됩니다.
- 비밀 값은 출력하거나 스냅샷에 저장해서는 안 됩니다.
- 권한 규칙 값, 쓰기 가능 루트 경로, 훅/도우미 본문 및 관련 없는 설정 값은 에이전트 설정 보고서에 보관해서는 안 됩니다.
- 권한 상태 스냅샷은 소스 경로와 설정 값을 제외해야 하며, 새 자율성 또는 정책 의미 변경은 검토를 요구해야 합니다.
- 결합 스냅샷은 권한 지정자와 도구 이름을 제외해야 하며, ASK/BLOCK 소스의 자동 권한, 와일드카드 확대, 출처 변경 또는 모호하거나 연결되지 않은 규칙을 안전한 연결로 표시해서는 안 됩니다.
- 런타임 증거는 원시 도구 목록과 예상 밖 필드를 거부하고, 관찰된 BLOCK/미설정 서버를 차단하며, 새로 관찰된 서버나 도구 개수 증가를 검토가 필요한 확대로 처리해야 합니다.
- 알 수 없는 증거가 신뢰로 바뀌어서는 안 됩니다.
- 차단 신호의 심각도를 출처 정보로 낮춰서는 안 됩니다.
- 지원하지 않는 보안 관련 구문은 안전하게 실패해야 합니다.
- 네트워크 조회는 명시적으로 수행하며, 관찰은 승인이 아닙니다.
- ALLOW는 정책 결과이지 안전 인증이 아닙니다.

설정 검사는 권고 기능입니다. 소스 파일 하나 또는 명시적으로 전달된 Claude/Codex 소스 스택을 읽고 지원되는 보안 필드에 대해 문서화된 우선순위를 계산할 수 있습니다. 활성 파일, 프로필, 환경 변수 재정의, 요구사항 또는 서버 전달 정책을 자동으로 찾지 않으며 보고된 정책이 실제로 활성화되었다는 것도 증명하지 않습니다. MCP 게이트는 구현된 강제 적용 경계로 유지되고, 에이전트 작업은 운영체제 및 런타임 샌드박스가 강제합니다.

결합 스냅샷은 MCP 검사/정책 결과와 명시적으로 전달된 런타임 설정에서 파싱한
자동 도구 권한이라는 두 정적 투영을 합성합니다. 실제 설정을 자동으로 찾거나 도구
호출을 가로채지 않습니다. `bound`는 관찰된 범위 제한 권한이 전달된 증거 아래에서
ALLOW 소스를 가리킨다는 뜻이며, 도구 구현이 안전하거나 런타임이 해당 파일을
로드했다는 뜻이 아닙니다.

런타임 증거는 권한이 있는 어댑터가 제공하는 세 번째 옵트인 투영을 추가합니다.
계약에는 도구 이름, 엔드포인트, 경로 또는 자격 증명이 아니라 서버 이름과 도구
개수만 포함됩니다. 인벤토리 다이제스트는 내부 상태만 검증합니다. 운영자는 별도의
신뢰할 수 있는 채널로 생성자를 인증하고 완전성을 확인해야 합니다.

## 의존성 정책

현재 런타임 코드는 Node.js 기본 제공 기능만 사용합니다. 새로운 의존성을 추가하려면 해당 기능을 플랫폼만으로 합리적으로 구현할 수 없는 이유, 패키지의 유지관리 및 보안 상태, 공급망 경계에 미치는 영향을 설명하는 이슈가 필요합니다.
