# 로드맵

<p align="right">
  <a href="./ROADMAP.md">English</a> | <strong>한국어</strong>
</p>

TrustDex는 초기 단계입니다. 이 로드맵은 방향을 공유하며 릴리스를 약속하지 않습니다.

## 진행 상황

- TrustDex 0.6.0은 Claude Code와 Codex 권한의 안전한 실패 검사를 추가했습니다.
- TrustDex 0.7.0은 값이 제거되고 자체 일관성을 검증하는 권한 상태 스냅샷,
  자율성 확대 검토 게이트, 버전 지정 JSON 스키마 및 공개 적대적 권한 픽스처를
  추가합니다.
- TrustDex 0.8.0은 문서화된 Claude Code 및 Codex 우선순위를 위한 명시적 병합 소스
  검사, 스키마 v2 소스 구성 증거 및 안전하게 실패하는 스택 테스트를 추가합니다.
- TrustDex 0.9.0은 MCP 정책/출처 결과와 자동 도구 권한 사이의 값 없는 Claude/Codex
  연결, 버전 지정 스키마, 드리프트 검토 및 비활성 픽스처를 추가합니다.
- TrustDex 0.10.0은 명시적인 값 없는 런타임 인벤토리 계약, 실제 경계 대조,
  노출 드리프트 검토, 버전 지정 스키마 및 픽스처를 추가합니다.
- TrustDex 0.11.0은 정확한 런타임 인벤토리의 Ed25519 생성자 인증, 제한된 만료/캡처
  나이, 스키마 v2 인증 상태와 재사용·다른 키·미래 시각·변조·미인증 증거를
  안전하게 실패시키는 테스트를 추가합니다.
- `main`에 미출시: VS Code·Cursor용 IDE 확장 게이트(정확한 버전 고정, 설치 파일 다이제스트, 서명된 재확인), 에이전트를 위한 버전 있는 실패 시 차단 `--decisions` 계약, 엄격한 정책 검증, 판정·정책·스냅샷 스키마 공개

## 현재: 경계 강화

- MCP JSON, Codex TOML, 스킬 및 플러그인 매니페스트의 적대적 픽스처 확장
- Claude Code와 Codex 모두의 적대적 권한 픽스처를 계속 확장
- 사람이 읽을 수 있는 모든 출력에 비밀 값이 계속 포함되지 않는지 검증
- 크로스 플랫폼 소스 및 경로 정규화 개선
- 안정적인 정책 및 스냅샷 스키마 규칙 문서화
- CI, CodeQL 및 릴리스 자동화를 재현 가능하고 검토 가능한 상태로 유지

## 다음: 실제 런타임 증거 강화

- 런타임이 권한 있는 안정적 인터페이스를 제공할 때만 구체적인 옵트인 어댑터 게시
- 배포용 공개 키 허용 목록, 교체 및 폐기 연결 지점 추가
- 메시지 수준 생성자 서명 주변의 전송 보호 문서화
- 값 없는 보고서를 유지하면서 MCP 표시 범위 밖으로 실제 증거 확장
- 지원하는 어댑터/런타임 버전의 테스트 기반 호환성 매트릭스 게시

## 그다음: 무결성 증명

- 레지스트리가 암호학적 해시를 제공할 때 변경 불가능한 패키지 아티팩트 검증
- 레지스트리 관찰을 정확한 패키지 버전 및 저장소 신원과 연결
- TrustDex 릴리스용 체크섬 또는 더 강력한 출처 게시
- 소유권 이전, 삭제된 릴리스, 게시 취소된 패키지 및 레지스트리 드리프트용 픽스처 추가

## 향후: 상호 운용성 확장

- 추가 에이전트 런타임 및 레지스트리용 어댑터 추가
- 테스트에 근거한 호환성 매트릭스 게시
- 조직 관리형 신뢰 저장소 및 검토 키 교체 탐색

## 도입 목표

프로젝트는 거짓 양성, 거짓 음성, 설정 형식 및 유지관리자 워크플로에 대해 민감하지 않은 피드백을 공유할 파일럿 사용자를 찾고 있습니다. 사용 관련 주장은 검증할 수 있을 때만 문서화합니다. 스타 수, 브랜딩 및 패키지 이름은 절대 보안 증거로 취급하지 않습니다.

## 참여 방법

실제 설정에서 TrustDex를 실행했다면 **Pilot feedback** 이슈 양식이 결과를 보고하는 가장 빠른 방법입니다. 그렇지 않으면 사용 사례와 민감 정보를 제거한 설정 형태를 설명하는 범위가 명확한 이슈를 여세요. 보안에 민감한 제안에는 예상 신뢰 경계와 우회 사례를 포함하세요.
