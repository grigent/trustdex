# 로드맵

<p align="right">
  <a href="./ROADMAP.md">English</a> | <strong>한국어</strong>
</p>

TrustDex는 초기 단계입니다. 이 로드맵은 방향을 공유하며 릴리스를 약속하지 않습니다.

## 진행 상황

- TrustDex 0.6.0은 Claude Code와 Codex 권한의 안전한 실패 검사를 추가했습니다.
- TrustDex 0.7.0은 값이 제거되고 자체 일관성을 검증하는 권한 상태 스냅샷,
  자율성 확대 검토 게이트, 버전 지정 JSON 스키마 및 공개 적대적 권한 픽스처를
  추가합니다.
- TrustDex 0.8.0은 문서화된 Claude Code 및 Codex 우선순위를 위한 명시적 병합 소스
  검사, 스키마 v2 소스 구성 증거 및 안전하게 실패하는 스택 테스트를 추가합니다.
- TrustDex 0.9.0은 MCP 정책/출처 결과와 자동 도구 권한 사이의 값 없는 Claude/Codex
  연결, 버전 지정 스키마, 드리프트 검토 및 비활성 픽스처를 추가합니다.
- TrustDex 0.10.0은 명시적인 값 없는 런타임 인벤토리 계약, 실제 경계 대조,
  노출 드리프트 검토, 버전 지정 스키마 및 픽스처를 추가합니다.
- TrustDex 0.11.0은 정확한 런타임 인벤토리의 Ed25519 생성자 인증, 제한된 만료/캡처
  나이, 스키마 v2 인증 상태와 재사용·다른 키·미래 시각·변조·미인증 증거를
  안전하게 실패시키는 테스트를 추가합니다.
- TrustDex 0.12.0은 VS Code·Cursor용 IDE 확장 게이트(정확한 버전 고정, 설치 파일
  다이제스트, 서명된 재확인), 에이전트를 위한 버전 있는 실패 시 차단 `--decisions` 계약,
  엄격한 정책 검증, 서명된 Codex 설정 검토, Codex 설정용 TOML 렉서, 러너별 패키지 신원
  검사, 교체·폐기를 지원하는 `--keyset` 검증 키 허용 목록, 출력 카나리 점검을 추가합니다.
- TrustDex 0.13.0은 원자적이고 심볼릭 링크에 안전한 CLI 출력, 시간 제한이 있는 출처 조회,
  npm 게시 취소·무결성 메타데이터의 실패 시 차단, 크로스 플랫폼 경로 인식을 추가하고,
  0.13.1은 IDE 확장 트리에 자원 한도를 적용합니다.
- TrustDex 0.14.0은 `check-install`(npm, pnpm, yarn, bun, npx, pip, uv, uvx, pipx, poetry,
  pdm 설치 명령의 오프라인 분석과 레지스트리 메타데이터 검사)과, 위험한 설치·설정 변조·
  자격 증명 읽기·권한 우회·자동 실행 항목을 막는 `claude-hook` `PreToolUse` 가드를 추가합니다.
- TrustDex 0.15.0은 SSH로 보내는 명령을 검사하고, 0.15.1은 로컬 스크립트의 1회 승인을
  스크립트 SHA-256에 묶습니다.
- TrustDex 0.16.0은 멈춘 행동을 소유자만 Slack으로 승인하는 `slack-approver`를 추가하고,
  0.16.1은 입력 리디렉션으로 넘긴 자격 증명 파일을 비밀 접근으로 판단합니다.
- TrustDex 0.17.0은 Claude Code 훅을 한 번에 설정하는 `trustdex init`을 추가하고,
  0.17.1은 내장 권고로 알려진 악성 PyPI 릴리스를 차단합니다.
- TrustDex 0.17.2는 무결성 단계를 시작합니다. `provenance-dropped`는 이전 버전에 있던
  provenance가 없는 최근 npm 릴리스를 표시하고, 내장 권고는 탈취된 npm 릴리스를 차단합니다.
  릴리스에는 체크섬, SBOM, GitHub 증명이 함께 게시됩니다.
- TrustDex 0.17.3은 소스를 신뢰 등록할 때(`provenance npm`, `trust-source npm`) npm 빌드
  provenance를 패키지가 선언한 저장소와 비교하고, 소유권 이전·삭제된 릴리스·yank된
  릴리스용 레지스트리 드리프트 픽스처를 추가합니다.
- TrustDex 0.18.0은 소스를 신뢰 등록할 때 npm 빌드 provenance의 Sigstore 번들을 고정된
  신뢰 루트로 오프라인 검증하고, 스킬·플러그인·MCP JSON 적대적 픽스처와 그 과정에서
  드러난 파서 수정을 추가하며, 캡처한 Claude Code `system/init` 이벤트를 런타임 인벤토리로
  바꾸는 `inventory-claude-init`을 추가합니다. 테스트로 확인하는
  [호환성 매트릭스](COMPATIBILITY.ko.md), [스키마 안정성 규칙](SCHEMAS.ko.md),
  [설계 노트](DESIGN_NOTES.ko.md)도 함께 게시합니다.
- 0.18.0 이후: 캡처한 Codex `mcpServerStatus/list` 요청·응답용
  `inventory-codex-mcp-status`, [Devin CLI](DEVIN.ko.md)와 [Gemini CLI](GEMINI.ko.md)용
  MCP 설정 어댑터.
- 미출시: 에이전트 가드의 경로 검사가 윈도우 드라이브 문자, `\\?\`·UNC 표기, 대소문자,
  `..`, 심볼릭 링크, 커널·펌링크 별칭, 홈 디렉터리 표기를 같은 대상으로 보며, 플랫폼별
  표기마다 시험이 있습니다.

## 현재: 경계 강화

- MCP JSON, Codex TOML, 스킬 및 플러그인 매니페스트의 적대적 픽스처를 계속 확장
- Claude Code와 Codex 모두의 적대적 권한 픽스처를 계속 확장
- 사람이 읽을 수 있는 모든 출력에 비밀 값이 계속 포함되지 않는지 검증
- 크로스 플랫폼 소스 및 경로 정규화 개선
- 형식이 바뀔 때 [스키마 안정성 규칙](SCHEMAS.ko.md)을 최신으로 유지
- CI, CodeQL 및 릴리스 자동화를 재현 가능하고 검토 가능한 상태로 유지

## 다음: 실제 런타임 증거 강화

- 런타임이 권한 있는 안정적 인터페이스를 제공할 때만 구체적인 옵트인 어댑터 게시 (Claude Code와 Codex 변환기가 있음. Gemini CLI와 Devin은 기계 판독형 세션 인벤토리를 문서화하지 않음, [런타임 증거](RUNTIME_EVIDENCE.ko.md) 참고)
- 메시지 수준 생성자 서명 주변의 전송 보호 문서화
- 값 없는 보고서를 유지하면서 MCP 표시 범위 밖으로 실제 증거 확장
- 어댑터가 출시되면 [호환성 매트릭스](COMPATIBILITY.ko.md)를 어댑터/런타임 버전까지 확장 ([설계 노트](DESIGN_NOTES.ko.md))

## 그다음: 무결성 증명

- 레지스트리가 암호학적 해시를 제공할 때 변경 불가능한 패키지 아티팩트 검증
- npm이 사용하기 시작하면 npm 빌드 provenance의 Rekor v2 로그와 RFC 3161 타임스탬프 지원 (서명·인증서 체인·SCT·로그 항목·머클 포함 증명은 오프라인으로 검증하며, 고정된 신뢰 루트에는 [갱신 절차](TRUST_ROOT.ko.md)가 있음)
- 레지스트리 관찰을 정확한 패키지 버전 및 저장소 신원과 연결
- TrustDex 릴리스용 체크섬 또는 더 강력한 출처 게시
- 소유권 이전, 삭제된 릴리스, 게시 취소된 패키지 및 레지스트리 드리프트용 픽스처 추가

## 향후: 상호 운용성 확장

- 추가 에이전트 런타임 및 레지스트리용 어댑터 추가 (Devin CLI와 Gemini CLI의 MCP 설정과 권한 설정은 지원함. 다른 레지스트리는 아직 아님)
- 테스트 기반 호환성 매트릭스를 새 런타임과 레지스트리로 확장
- 조직 관리형 신뢰 저장소 및 검토 키 교체 탐색

## 도입 목표

프로젝트는 거짓 양성, 거짓 음성, 설정 형식 및 유지관리자 워크플로에 대해 민감하지 않은 피드백을 공유할 파일럿 사용자를 찾고 있습니다. 사용 관련 주장은 검증할 수 있을 때만 문서화합니다. 스타 수, 브랜딩 및 패키지 이름은 절대 보안 증거로 취급하지 않습니다.

## 참여 방법

실제 설정에서 TrustDex를 실행했다면 **Pilot feedback** 이슈 양식이 결과를 보고하는 가장 빠른 방법입니다. 그렇지 않으면 사용 사례와 민감 정보를 제거한 설정 형태를 설명하는 범위가 명확한 이슈를 여세요. 보안에 민감한 제안에는 예상 신뢰 경계와 우회 사례를 포함하세요.
