# 방어적 보안 연구

<p align="right">
  <a href="./SECURITY_RESEARCH.md">English</a> | <strong>한국어</strong>
</p>

TrustDex는 AI 에이전트가 서드파티 도구에 접근하기 전에 내리는 신뢰 결정에 관한 합법적인 방어적 연구를 위해 개발됩니다. 이 문서는 해당 작업의 승인, 안전 및 공개 경계를 정의합니다.

## 목적

이 연구는 사람이 또는 정책이 명시적으로 신뢰할 때까지 확장을 사용할 수 없게 유지하는 데 관찰 가능한 설정, 출처, 무결성 및 기능 증거가 충분한지 묻습니다. 현재 작업은 다음에 중점을 둡니다.

- 고정되지 않았거나 대체된 패키지
- 실행 시 설치 및 셸 런처
- URL에 포함된 자격 증명과 안전하지 않은 원격 전송
- 값을 보관하지 않고 비밀 정보를 포함하는 환경 변수 이름 감지
- 소스, 출처, 결정, 지문 및 기능 드리프트
- 서명된 검토 기록과 신뢰 관련 변경 후 재검토
- 지원하지 않는 구문에서 안전하게 실패해야 하는 파서 동작
- Claude Code 권한 설정의 자동 행동 권한
- Codex 샌드박스, 승인, 네트워크, 쓰기 가능 루트, 웹 검색 및 서브에이전트 설정
- 구조적 권한 상태 드리프트 및 에이전트 자율성 확대 시 재검토

의도한 결과물은 재현 가능한 픽스처, 회귀 테스트, 문서화된 제한 사항 및 에이전트 개발자와 운영자를 위한 실용적인 완화책입니다.

## 승인 경계

연구는 다음으로 제한됩니다.

- 연구자가 소유한 시스템과 계정 또는
- 연구자가 테스트할 명시적인 승인을 받은 시스템 그리고
- 민감하지 않은 픽스처를 사용하는 격리된 로컬 또는 연구 전용 테스트 환경

TrustDex 연구는 관련 없는 공개 시스템을 테스트할 권한을 부여하지 않습니다. 자격 증명 탈취, 지속성 확보, 파괴적 작업, 데이터 유출, 대규모 악용, 무단 접근, 악성 코드 배포 및 다른 사람의 보호 조치 우회는 제외됩니다.

## 안전한 테스트 데이터

체크인된 적대적 픽스처는 비활성 설정 문서입니다. 예약된 `.invalid` 도메인, 존재하지 않는 패키지 네임스페이스 및 명백한 자리표시자 값을 사용합니다. TrustDex는 검사 중에 MCP 서버를 실행하지 않습니다.

테스트는 비밀 정보로 보이는 값, URL 자격 증명, 쿼리 값 및 비공개 경로가 검사 결과에 나타나지 않는지 확인합니다. 실제 자격 증명, 비공개 엔드포인트, 개인 데이터 또는 프로덕션 서비스가 필요한 픽스처는 이 저장소에서 허용되지 않습니다.

## 방법

각 연구 사례에는 다음이 포함되어야 합니다.

1. 최소한의 검토 가능한 입력 픽스처
2. 예상 신뢰 관련 신호
3. 이름이 지정된 정책에서 예상되는 `ALLOW`, `ASK` 또는 `BLOCK` 결정
4. 자동화된 회귀 테스트
5. 문서화된 제한 사항 또는 가능한 우회 조건

`ALLOW` 결과는 관찰된 증거가 선택한 정책과 일치한다는 의미일 뿐입니다. 임의의 코드가 안전하다는 증거로 표현해서는 안 됩니다.

## 발견 사항 처리

사용자를 위험에 빠뜨릴 수 있는 잠재적인 TrustDex 취약점은 [SECURITY.ko.md](../SECURITY.ko.md)를 따라야 합니다. 다른 프로젝트에서 발견한 사항은 해당 프로젝트의 승인된 보안 채널을 통해 공개해야 하며, 합리적인 공동 공개 절차가 끝나기 전에 게시해서는 안 됩니다.

공개 보고서에서는 자격 증명, 비공개 엔드포인트, 독점 프롬프트, 개인 데이터 및 불필요한 위험을 만드는 악용 세부 정보를 제거해야 합니다. 연구 노트는 문제를 재현하고 수정하는 데 필요한 최소한의 증거를 우선해야 합니다.

## 출력 비식별 규칙

TrustDex는 **이름과 식별자**를 보고할 수 있습니다. 서버 이름, 설정 키, 환경 변수 이름, 헤더 이름, 신호 이름, 확장 ID와 알려진 레지스트리 라벨, 원격 호스트와 오리진, 자격 증명과 쿼리 값을 뺀 패키지 지정이 여기에 해당합니다. git ref는 버전을 고르는 값이라 유지합니다. **값**은 절대 보고하지 않습니다. 환경 변수와 헤더 값, URL 자격 증명과 쿼리 값(패키지 지정 안의 것 포함), 민감한 명령줄 플래그 값, 권한 지정자, 훅과 헬퍼 명령, 디렉터리와 쓰기 가능 루트 경로, 신뢰할 수 없는 매니페스트 텍스트, 잘못된 입력에서 인용한 내용이 여기에 해당합니다. 이 규칙은 모든 출력 모드(사람용, `--json`, `--decisions`)의 stdout과 stderr, 그리고 TrustDex가 쓰는 모든 파일에 적용됩니다. 원래의 허용 항목을 의도적으로 보존하는 MCP·Codex 게이트 출력만 예외입니다.

`test/secret-canary.test.mjs`가 검사 대상 입력에 대해 이 규칙을 강제합니다. 그 파일 맨 위에 나열된 값 위치에 고유한 카나리를 심습니다. 대상은 MCP JSON, Claude MCP JSON, Claude 설정과 스택, Codex TOML, Codex 설정과 스택, 스킬, 플러그인 매니페스트, IDE 확장입니다. 그다음 세 가지 출력 모드의 검사 명령과 스냅샷, 권한 상태, 결합, 게이트, 승인, 재확인(변경 전후), diff, diff-permissions, diff-bindings, sign, verify를 실행합니다. 카나리가 대소문자와 상관없이 출력이나 기록된 파일에 나타나면 실패합니다. 두 번째 단계는 잘못된 입력을 검사합니다. 정책과 신뢰 저장소 파일은 운영자가 작성하는 신뢰 입력이라 범위 밖이고, 런타임 인벤토리 명령은 값이 없는 인벤토리만 받습니다. 새 입력 형식, 값 위치, 명령을 추가할 때는 같은 변경에서 이 검사도 확장하세요.
