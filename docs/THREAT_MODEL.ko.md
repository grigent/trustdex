# 위협 모델

TrustDex는 하나의 좁은 질문을 다룹니다.

> **사용자의 정책에 따라 에이전트가 이 확장을 보거나 이 자동 행동 권한을 받도록 허용해야 하는가?**

## 범위 내

- 알 수 없거나 승인되지 않은 MCP 소스
- 검토 없이 변경될 수 있는 유동 패키지 버전
- 검토된 스냅샷 사이의 소스 변경
- 출처 주장의 변경 또는 소멸
- 새로 관찰된 셸, 파일 시스템, 네트워크, 설치, 와일드카드 도구 또는 비밀 환경 신호
- 정책 회귀로 발생하는 안전하지 않은 도구 노출
- 검토된 레지스트리 무결성 메타데이터와 일치하지 않는 패키지 바이트로의 대체
- 설정된 패키지 버전이 무결성 검증된 아티팩트 버전에서 벗어남
- 서명된 신뢰 기록이 있을 때 검토된 스냅샷의 변조
- 광범위한 셸, 파일 시스템, 네트워크, MCP 또는 서브에이전트 작업을 조용히 자동 승인하는 Claude Code 권한 규칙
- 샌드박스를 제거하거나 승인을 생략하거나 네트워크 접근 또는 쓰기 가능 루트를 추가하는 Codex 설정
- 명시적인 검토 없이 변경되는 행동 권한 설정
- 값이 제거된 구조적 기준 상태보다 확대되는 Claude 또는 Codex 권한 상태
- 명시적으로 전달된 Claude 또는 Codex 설정 소스 사이의 우선순위 변경
- 서버의 정책/출처 결과와 더 이상 일치하지 않는 자동 MCP 도구 권한
- 실제 도구 경계를 가리는 와일드카드, 일치하지 않거나 모호한 권한
- 차단·검토 필요·미설정 MCP 서버를 노출한다고 명시적으로 보고한 런타임 인벤토리
- 서버 표시 범위 또는 도구 개수로 확대되는 실제 런타임 인벤토리
- 서명된 런타임 인벤토리의 변조, 만료/캡처 나이 이후 재사용, 미래 시각 지정 또는 다른 키 대체
- 고정되지 않았거나, 검토하지 않은 버전으로 몰래 업데이트되었거나, 검토 후 설치 파일이 바뀐 에디터 확장(VS Code, Cursor)
- 사이드로드되었거나, 에디터 설치 기록에 없거나, 설치 기록과 일치하지 않는 에디터 확장 폴더

## 신뢰 경계

TrustDex가 신뢰하는 것:

- 자체 정책/설정을 읽을 수 있을 정도의 로컬 호스트
- 사용자가 명시적으로 설정한 정책
- 신뢰 저장소 유지관리자가 검토한 범위 내의 출처 증거
- 사용자가 신뢰할 수 있는 채널을 통해 얻은 경우에만 공개 키

TrustDex는 익숙한 프로젝트 이름, 스타 수, 패키지 이름 또는 로고를 출처로 취급하지 **않습니다**.

## 범위 밖

- 임의의 서드파티 코드가 악성이 아님을 증명
- 도구 실행 샌드박싱
- 모든 프롬프트 인젝션 기법 탐지
- 모든 전이 의존성의 취약점 검사
- 무결성이 일치하는 패키지 바이트가 악성이 아님을 증명
- 로컬 신뢰 저장소 주장만으로 게시자 소유권을 독립적으로 증명
- 완전히 침해된 호스트 보호
- 도난당한 서명 비공개 키로부터 보호
- 모든 활성 설정 소스, 프로필, 환경 변수 재정의, 요구사항 또는 서버 전달 정책의 자동 탐색
- 명시적으로 병합한 설정 투영이 런타임에서 활성화된 정책임을 증명하는 것
- Claude Code 또는 Codex 행동 권한의 런타임 강제 적용
- 서명되지 않은 권한 상태 스냅샷 작성자의 인증
- 결합 스냅샷이 실행 중인 에이전트가 실제로 불러온 파일을 반영함을 증명하는 것
- 개별 MCP 도구 호출을 런타임에서 가로채거나 강제하는 것
- 인벤토리 완전성 증명 또는 침해된 어댑터나 탈취된 생성자 키의 거짓 증거 서명 방지
- 실제 Claude/Codex 세션을 자동으로 찾거나 비공개 상태를 읽는 것
- 에디터가 확장 업데이트를 설치하는 것을 막거나, 설치된 확장이 이미 호스트에 만든 변경을 되돌리는 것
- TrustDex에 지정한 디렉터리가 아닌 다른 디렉터리에서 불러온 확장
- 패키지 러너가 실행되는 디렉터리나 그 상위 디렉터리의 파일(`.npmrc`, `package.json`, `node_modules/.bin`), 그리고 사용자·호스트 수준의 러너 설정(`~/.npmrc`, uv 사용자 설정, 실행하는 셸의 환경 변수). TrustDex는 러너 인자와 서버 자체의 `env` 블록을 검사하며, 실행 디렉터리나 호스트는 검사하지 않음

## 중요한 실패 모드

유효한 서명은 신뢰 기록이 해당 비공개 키로 서명되었고 연결된 스냅샷 다이제스트가 변경되지 않았음을 증명합니다. 원래 검토가 정확했다는 것은 증명하지 않습니다.

마찬가지로 유효한 런타임 인벤토리 증명은 고정된 생성자 키가 검사된 시간 제한 안에서
정확한 값 없는 인벤토리에 서명했음을 증명합니다. 생성자가 로드된 모든 도구를
관찰했거나 런타임을 진실하게 보고했다는 사실은 증명하지 않습니다.

## 설계 원칙

TrustDex는 누락된 증거를 신뢰로 변환해서는 안 됩니다. 알 수 없는 출처는 추측할 이유가 아니라 정책 입력입니다.
